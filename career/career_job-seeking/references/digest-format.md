# Digest Format Reference

The weekly job hunt digest is generated by `scripts/generate_digest.py` and follows this exact layout.

## Digest Email Header

```
Search Profile: Senior Power Systems Engineer, DER Integration, Grid Integration
Oakland, Bay Area, Remote USA
```

After the header, **Market Signals** are injected (if present) — right before the first tier section. The postscript file `/tmp/digest_postscript.txt` (written by Phase 5) is loaded via `load_postscript()` and placed at the top of the email, not appended at the bottom.

```
MARKET SIGNALS THIS WEEK
  - Grid skills crisis accelerating
  - Renewable workforce projected to double by 2030
```

## Per-Offer Entry Template

```
#NNN  Title @
Company Name
  Location: City, State or Remote
  Match Score: X/10
  Salary: $Lowk-$Highk
  Notes: Clean summary of job info, skills required, responsibilities.
URL: https://example.com/job/123
———
#NNN: SCORE:  
FEEDBACK: 
```

### Format Rules

| Element | Rule |
|---|---|
| **ID line** | `#{id}  {title} @` — flush left, no indent. `@` at end of line, company on next line flush left. |
| **Details** | Indented 2 spaces. `Location:`, `Match Score:`, `Salary:`, `Notes:` — single space after colon. |
| **Score label** | `Match Score: X/10` (not `Score:` or any other variant) |
| **Notes** | Only job-relevant content. Enrichment/audit metadata lines are stripped. See [Notes Cleaning](#notes-cleaning) below. |
| **URL** | `URL:` prefix, flush left, no indent. |
| **Separator** | Em-dash triple `———` between the URL line and scoring block. |
| **Scoring block** | `#{id}: SCORE:  ` (two trailing spaces for Maxime to type into) then `FEEDBACK: ` on next line. Both uppercase. |

### Notes Cleaning

The `clean_notes()` function strips all lines starting with these prefixes (they are enrichment audit trails, not job info):

- `Salary enriched`
- `JD summary` — BUT the content *after* the colon is preserved (e.g. `JD summary 2026-04-28: Do grid stuff` → `Do grid stuff`)
- `Verified active`
- `Closed:`
- `Notes enriched`

When enriching notes in Job Registry Maintenance, do NOT write these prefix lines. Append only the actual summary content directly. Legacy entries still containing them will be cleaned by `generate_digest.py`. Registry maintenance runs should also strip them (see `job-data-enrichment.md`).

## Tier Section Layout

```
==================================================
  TIER N -- LABEL
==================================================

<offer 1>
<offer 2>
<offer 3>
```

Tier labels:
- **1** → `OAKLAND / EAST BAY  (PRIMARY)`
- **2** → `BAY AREA  (SECONDARY)`
- **3** → `RELOCATION`

```
--------------------------------------------------
SUMMARY
  Tier 1 (Oakland / East Bay):  {count} offers in registry, top 3 shown
  Tier 2 (Bay Area):            {count} offers in registry, top 3 shown
  Tier 3 (Relocation):          {count} offers in registry, top 3 shown
  Top pick: {title} @ {company} (#{id})

REGISTRY STATS
  Total in registry   : {total}
  Tier 1 (Oakland/Remote): {t1}   Tier 2 (Bay Area): {t2}   Tier 3 (Relocation): {t3}
  Awaiting your review: {unreviewed}
  Shortlisted (score>=3): {shortlisted}
  Applied             : {applied}
  Passed / discarded  : {passed}
  New this week       : {new}
--------------------------------------------------
```

## How to Reply Section

```
==================================================
HOW TO REPLY
==================================================
Only score the offers you have an opinion on --
unscored offers will reappear next week.

Score guide:
  5  = Must apply ASAP (Andy reminds you after 1 week if not applied)
  3-4 = Should apply -- added to shortlist
  1-2 = Low priority, maybe someday
  0  = Pass (kept in registry, not surfaced again soon)
  -1 = Discard permanently

==================================================
Generated by Andy | Career Manager
```

> **Note:** The HOW TO REPLY section was shortened on 2026-05-05 per Maxime's request. The previous version included a template (`SCORES: #<id>=<score> ...`) and an Example reply block. These were removed because scoring blocks are now inline per-offer (at the end of each entry), so the template is redundant. The "unscored offers will reappear next week" line was kept to clarify that scoring is optional.

## File Layout

The digest body is written to `/tmp/digest_body.txt` for debugging. Stats (subject, counts) go to `/tmp/digest_stats.json`. The email is sent from `"Andy" <maximes.butler@gmail.com>` to `maxime+hireme@baudette.fr`.

## Email Subject Format

```
Weekly Job Hunt - {Month} {Day}, {Year} - {unreviewed_count} opportunities found
```

## Implementation

The formatted is generated by `scripts/generate_digest.py`:
- `format_offer()` — renders a single offer entry
- `clean_notes()` — strips enrichment metadata
- `format_tier_section()` — renders a tier with its offers
- `build_digest()` — assembles the full body
- `load_postscript()` — reads market signals from `/tmp/digest_postscript.txt` and passes to `build_digest()` for top-injection
